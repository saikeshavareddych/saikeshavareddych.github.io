The problem

Security scanning already existed. It ran, it produced a report, and the report went into an artifact nobody opened. Findings accumulated for months because nothing in the pipeline changed behaviour based on them.

An advisory gate is not a gate. It is a log line that costs runner minutes. The interesting problem was not adding scanners, it was making the pipeline refuse to promote, without making engineers hate it enough to route around it.

Constraints

  • The security stages cannot dominate wall-clock time. A pipeline people wait on is a pipeline people skip.
  • Failures must be specific. "Scan failed" teaches nothing. The gate has to say which finding, in which file, and what clears it.
  • There has to be an exception path. A gate with no documented way past it will be disabled the first time it blocks a release at 6pm.
  • Every decision must be auditable after the fact. Who approved what, against which finding.
  • No static AWS credentials in CI.

Architecture

Six delivery stages run left to right. Beneath each one sits a gate that blocks it: secret scanning at commit, SAST at build, composition and licence analysis at test, image scanning and signing at package, dynamic analysis against the deployed staging environment, and a final policy gate with human approval before the production canary.

The gates run in parallel with each other where they can, so the added wall-clock cost is roughly one gate, not six. Underneath runs the supply-chain spine: federated credentials into AWS, SLSA provenance and an SBOM attached to every release, and automatic rollback triggered by error-budget burn rather than by an alert someone has to read.

Decisions and trade-offs

Every one of these had a cost. Listing the cost is the point.

DecisionWhyWhat it costs
Gates fail closed, with a written exception pathA finding either blocks promotion or it is not a finding. Behaviour changes, so the backlog gets worked.Requires an exception process with an owner and an expiry date, which is organisational work, not technical work.
Trivy across filesystem, image and IaC instead of a specialist per layerOne tool, one ignore file, one output format to parse. Far less glue.Less depth than a dedicated scanner in any single layer. I accepted shallower coverage for something that would actually stay maintained.
Keyless signing with cosignNo signing key to store, rotate or lose. Identity comes from the workflow itself.Adds a hard dependency on public transparency-log infrastructure being reachable during the build.
Rollback triggered by burn rate, not by error countA brief spike during a deploy is normal. Sustained budget burn is not. This distinguishes them without a human in the loop.Needs an SLO defined before the pipeline is useful, which pushes work upstream into service design.
Provenance attached at package time, not at deploy timeThe attestation describes the thing that was actually built, from the commit that built it.Rebuilding an old release requires the original workflow to still exist; the pipeline becomes part of the artifact's history.

What it achieves

Measured as design targets for the build:

  • A critical finding stops promotion. There is no configuration in which it merely warns.
  • Every release carries an SBOM and a signature that can be verified independently of the pipeline that produced it.
  • Added wall-clock cost of the full gate set is roughly the cost of the slowest single gate.
  • No AWS access key exists in the repository, the runner, or the organisation secrets.
  • A failed production canary reverts without anyone being paged first.

What I would change

I built the exception path in week three, after the gates had already blocked a release twice. Both times the pressure to just disable the gate was real, and the only reason it survived was that I was the one holding the switch.

The exception path is not a follow-up task. It is part of shipping the gate. A gate without one is a gate that gets deleted the first time it is inconvenient, and then you have neither the gate nor the trust to re-add it.
